1 项目概览

一句话定义：面向银发群体的网页代驾智能体。老人用口语或语音说出需求，AI 在真实网页流程中自主完成选科室、选时段、填就诊人、核对提交的全过程；凡是不可撤销的动作，必须本人点一下确认才会执行。

范式反转能力优先授权门禁双链路兜底标准 MCP多站点复用零成本可跑

不是"AI 告诉你怎么做"，而是"AI 替你做完，你只负责授权"。交互的主语从人变成了智能体。

当前可演示状态（v0.2）：两个被代驾站点（医院挂号 / 医保缴费）端到端跑通；四智能体链路、授权门禁闭环、MCP 工具层均已实测；评测 94/94 项断言通过；不需要任何 API Key 即可完整演示（npm run demo）。

2 需求与痛点（2026 真实社会背景）

  • 公共服务全面线上化，但老年人被流程挡在门外：挂号需要 4 步以上操作、10 余个表单字段。
  • 术语鸿沟：老人说的是"膝盖上下楼疼"，网页给的是"骨科 / 内科 / 外科"下拉框 —— 这中间缺一层症状到科室的语义映射。
  • 不敢点错：填错身份证、误触提交，后果不可撤销，于是很多老人干脆放弃线上服务。
  • 现有"适老版"只是放大字号，交互范式没变，依然要求人去适应机器。

为什么用 iframe + 能力协议

  • 保持"这是第三方网站"的真实感，Agent 通过跨文档消息驱动它，而非直接改 React 状态；
  • 能力清单由站点声明，Agent 只能按契约调用 —— 天然形成防幻觉闸门；
  • 同一套协议直接对外暴露为标准 MCP 工具，真实站点只需实现同样的服务端契约即可接入。

4 工作流编排

4.1 四个智能体的职责边界

智能体输入输出是否允许调用模型
Planner用户原话 + RAG 上下文 + 已收集字段结构化任务 JSON（含缺失项与人话追问）是（失败降级规则引擎）
Navigator当前页结构 + 能力清单 + 任务目标 + 历史动作单个动作 JSON（能力 id + 值 + 风险）是（失败降级规则引擎）
Guardian待执行动作 + 会话上下文风险等级 + 是否需授权 + 人话解释仅生成解释文本
Reporter执行结果 / 回执80 字以内通俗播报是（失败用模板）

4.2 执行时序

用户输入
  → 注入检测（命中越权指令则直接拦截）
  → Planner：抽取槽位 + RAG 映射科室；缺必填则输出追问并停止
  ┌─ 循环（最多 10 步）───────────────────────┐
  │ Navigator 选动作                           │
  │ if 动作不在能力清单 → 丢弃并重试（防幻觉）  │
  │ Guardian 裁决：high → 暂停并请求人工授权    │
  │ 执行（确定性代码，模型不参与）              │
  │ 推送 tool 事件 + page 事件（页面实时联动）  │
  └───────────────────────────────────────────┘
  → 提交成功生成回执 → Reporter 播报（可选语音）

4.3 为什么把执行做成确定性代码

模型的输出只用于"决策"（选哪个动作、填什么值），真正的写入、跳转、提交全部是普通 TypeScript 函数。好处是：可审计、可回放、可回滚，且模型抽风时也不会产生越界副作用。

5 提示词设计

版本：2026.10.10-v1，全部提示词集中在 lib/agents/prompts.ts，变更需同步 prompts/CHANGELOG 与评测集。

5.1 设计原则

  • 输出强约束：只输出 JSON，并在 system 中给出完整字段示例；解析失败时追加 FALLBACK_SYSTEM 重试一次，再失败则交规则引擎。
  • 红线前置：Navigator 的提示词第一条就是"只能从能力清单中选择，绝不允许臆造 id"，把幻觉风险压在决策之前。
  • 角色语域约束：Reporter 明确要求"不用技术术语、句子要短、控制在 80 字"，让输出适配老年听众。
  • 知识注入而非知识依赖：症状→科室映射由 RAG 提供，提示词要求"必须依据 <knowledge>，未命中则置空并追问"。

5.2 Planner 提示词（节选）

你是「小鱼儿」的任务规划器，服务对象是中国老年人。
规则：
1. 症状要映射到科室时必须依据 <knowledge>，不得凭空判断；未命中则 department 置空并在 ask 中询问。
2. 日期：相对词「今天/明天/后天」原样保留；没说日期则默认「明天」并说明。
5. 就诊人姓名、身份证号、手机号属于必填项；缺失时不要编造，改为在 ask 中用人话追问一次，一次只问一类。
6. 严禁输出任何 JSON 以外的内容。

输出：{"thought":"","plan":{...},"missing":[],"ask":"","stop":true}

5.3 健壮性处理

  • JSON 提取器 extractJson 兼容代码块包裹、前后废话、截断；
  • 流式输出中 thought 字段置于首位，前端可边流边解析展示"思考过程"；
  • 模型调用异常（网络/限流）统一 catch，切规则引擎并在轨迹中明示。

6 工具与能力配置

6.1 能力清单（Capability Registry）

每个页面在运行时被编译为能力列表，等价于对外暴露的 MCP 工具清单：

{
  "id": "fill:idCard",
  "verb": "fill",
  "target": "idCard",
  "label": "填写「身份证号」",
  "risk": "medium",
  "params": ["value"],
  "description": "18 位身份证号"
}

6.2 与 MCP 的同构关系

MCP 概念本项目实现说明
Tools / ListToolslistCapabilities(pageId)按页面动态编译，随流程推进而变化
Tools / CallToolexecuteCapability(session, cap, value)确定性执行，返回结构化结果
Resources页面结构 + 会话状态通过 page 事件推送
Sampling 之外的人工环路need_confirm + /api/confirm高危动作的人工授权回路

6.3 站点侧契约

被代驾站点的每个可操作单元都带 data-cap-id 与 aria-label，与能力 id 一一对应；这既服务 Agent，也天然提升了无障碍访问能力。

7 MCP 工具层

能力清单不只是内部抽象 —— 它同时以 标准 MCP（Model Context Protocol）服务器的形态对外暴露，实现于 app/api/mcp/route.ts，遵循 JSON-RPC 2.0。

POST /api/mcp
  initialize   → 声明协议版本、serverInfo 与能力
  tools/list   → 把两个站点的全部页面能力编译成 MCP 工具清单
  tools/call   → 执行单个能力，返回结构化结果

工具命名规则：  <siteId>__<verb>_<target>
  例：city-hospital__fill_department   （填写就诊科室）
      city-hospital__click_submit      （提交预约，高危）
已实测：tools/call 调用 city-hospital__fill_department 返回 ok:true 与推进后的页面状态；在「选择科室」页调用高危的提交动作，被防幻觉闸门拦截并返回 available 可用能力列表。

7.1 为什么这一步很关键

  • MCP/工具集成从"写在文档里"变成"可被第三方客户端真实调用"；
  • 高危动作的授权门禁在 MCP 通道上同样生效，不会因为换入口而失守；
  • 意味着一个真实政务站点只要暴露同构的能力接口，本 Agent 无需改代码即可代驾。

8 多站点复用

为证明「能力协议可跨站点复用」，项目中内置了两个领域完全不同的被代驾站点，它们共用同一套 Planner / Navigator / Guardian / Reporter、同一份安全策略、同一个 MCP 工具层。

站点路由业务关键槽位高危动作
市第一人民医院/sim/hospital预约挂号科室 / 医生类型 / 就诊日期时段 / 就诊人提交预约（high）
市民之家政务大厅/sim/citizen-hall医保 / 社保缴费办理事项 / 缴费年度 / 档次 / 参保人确认缴费（high）
新增一个站点的成本：只写一份 SiteDef（页面结构 + 字段 + 动作 + 领域约束 + 槽位抽取规则 + 回执格式），登记进 lib/sim/registry.ts 即可。Agent 层、安全层、MCP 层、前端渲染器一行都不用改 —— 这正是「能力优先于 DOM」的直接收益。
给老人自己点的挂号页（纯静态、零框架）：除「说一句话由智能体代驾」之外，项目另有一份 public/elder/index.html —— 全程点选不用打字（全页 0 个输入控件）、每步只做一件事、可语音朗读、可调字号并记忆、简体 / 繁體 / 英文 三语文案与语音同步切换（中文模式下界面不出现英文单词，语言切换器也随当前语言变）、提交前弹确认窗防误点；页面对外声明 9 项标准能力，后续可由智能体通过 XiaoYuEr.call() 驱动，越权参数一律拒绝、高危提交必须 granted: true。真实挂号流程的逐条审核与提炼见 docs/hospital-flow-notes.md，自检命令 npm run check:elder（31 项断言）。

手机上打开是乱码怎么办：文件本身是 UTF-8，但常见静态服务器只对 .html/.js/.css 返回 text/html、text/javascript、text/css 而不带 charset；HTML 还能靠 <meta charset> 自救，外链的 JS/CSS 没有任何编码线索，部分手机浏览器会按 GBK 解析 → 电脑上正常、手机上乱码。本项目做了三层防护（HTML 双重声明 / 外链写 charset / CSS @charset + JS 带 BOM），并额外提供 npm run build:elder 生成的单文件版 standalone.html：样式脚本全部内联，编码只由 <meta charset> 决定，手机端一定认。自己起服务请用 npm run serve:static（文本响应强制带 charset=utf-8，会打印局域网地址）；自建 nginx / Apache 各补一行 charset utf-8; / AddDefaultCharset UTF-8 即可。

页内还有一位语音智能助手：点右下角「小鱼兒」对它说话，浏览器语音识别后交给本地规则引擎（离线可用）理解成动作，再只走能力清单去点页面（跳步骤、点症状、点医生、点日期时段、选付款、朗读、调字号）；不支持语音时自动降级为「常说的话」点选卡片，全程依然不用打字。说到「确认预约」只把确认窗叫出来，仍要本人点一下或本人说一声「确认」。想换成真实大模型时挂一个决策函数即可：window.XiaoYuErAI.setPlanner(fn)，它出错或给出越权动作会自动回落到规则引擎。

手机端专门打磨过：用真实手机视口（390×844）逐屏核对，顶栏固定高度从 223px 压到 124px（一屏多露出近 100px 内容）；悬浮的「跟我说话」按钮会按底部操作栏的实际高度动态避让（--actionbar-h），不再压住「需要帮助」；各步渲染做了分块隔离，任一数据缺失都不会让整页渲染崩掉。这些都有断言守着，回不去。

9 RAG 知识库

知识切片共 10 条办事指南（症状→科室、必备材料、放号时间、退改规则、老年人便利服务、医保缴费等）。检索采用中文二元组 + 英文词的 TF-IDF 打分，零外部依赖，可在边缘运行，代价是无需引入向量数据库即可稳定命中。

RAG 是否真的提升了效果？能验证：没有知识库时，"膝盖疼"这类口语无法映射到骨科，Planner 只能追问或直接猜错；接入后，检索命中「症状与科室对应：骨关节」切片，科室准确率显著提升。这也是评测集里的一条硬用例。

后续规划：如接入真实政务数据源，可替换为向量检索（BGE-M3 + 本地向量库），检索器接口 retrieve(query, topK) 保持不变。

11 零成本部署

作品全程可零成本运行与演示，这是硬约束而非口号，分三层保证：

层做法
模型层lib/agents/llm.ts 内置多个 OpenAI 兼容 Provider 预设（智谱 GLM 免费档 / SiliconFlow / OpenRouter / DeepSeek / 本地 Ollama 等），只改 LLM_BASE_URL + LLM_MODEL + LLM_API_KEY 三个环境变量即可切换；不填任何 Key 也能完整演示
兜底层无 Key / 调用失败 / 输出不可解析 → 自动切规则引擎，行为完全一致，仅"思考"的文字由模板生成，轨迹中会明示当前引擎
依赖层RAG 用零依赖的中文二元组 TF-IDF 检索（免向量数据库）；评测脚本、演示启动器均为 Node 原生实现，不引入额外依赖
# .env.local —— 三种典型零成本配置（任选其一）

# A. 智谱 GLM 免费档
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_MODEL=glm-4-flash

# B. SiliconFlow 免费模型
LLM_BASE_URL=https://api.siliconflow.cn/v1
LLM_MODEL=Qwen/Qwen2.5-7B-Instruct

# C. 本地 Ollama（完全离线，零费用）
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL=qwen2.5:7b
一键演示：npm run demo 会自动检查环境、提示模型链路状态、启动服务并打印演示入口与建议话术；服务不可用时会明确提示先执行 npm install。

12 测试与 AI 辅助验证

12.1 AI 辅助用例生成

用大模型批量生成老人口语变体（方言词、错别字、含糊症状、多意图混合），再人工抽样校准，形成回归用例集：

  • 症状类：「我这膝盖上下楼疼」「头晕得厉害」「眼睛模糊看不清」
  • 信息缺失类：只说症状不说姓名 / 只给姓名不给身份证
  • 异常输入类：身份证位数错误、手机号非法、含越权指令
  • 边界类：直接指定专家门诊、要求下午时段、中途要求改科室

12.2 自动化判定

采用 规则断言（确定性）+ LLM-as-judge（语义）双判定，覆盖医院挂号与政务缴费两个站点：

  • 规则断言（确定性）：字段映射是否正确（如"膝盖上下楼疼 → 骨科"、"2027 年 → 2027 年度"）、缺失信息是否追问、high 动作是否出现过 need_confirm、授权后能否续跑闭环、页面状态中敏感值是否脱敏、越权指令是否被拦截；
  • 模型判定（语义）：追问是否话术得体、播报是否老人可读、方案是否合理；
  • 轨迹评估：每步动作是否命中能力清单、是否存在无效重试（冗余步数惩罚）。
当前结果：10 个用例、94/94 项断言全部通过（npm run eval，报告见 scripts/eval-report.md）。
过程中评测抓出并修复了 3 个真实缺陷：① 动作步数上限过小导致高危授权门禁实际未生效；② 注入检测正则过窄，漏判"忽略你之前的所有指令"；③ 新增站点后"绕过授权"类话术未被拦截。这三条都是仅靠人工点页面很难发现的。

备注：LLM-as-judge 与 AI 用例生成需要配置 LLM_API_KEY，未配置时自动降级为纯规则断言，评测依然可跑。

16 快速开始：安装与运行

环境要求

Node.js ≥ 18.18（推荐 20 LTS / 22 LTS）。无数据库、无外部服务依赖。

三步启动

npm install          # ① 安装依赖
npm run dev          # ② 启动开发服务器

③ 浏览器打开 http://localhost:3000，看到主控台即成功。也可以用一键脚本 npm run demo，它会检查环境、拉起服务并打印入口与推荐话术。

停止服务

在运行 npm run dev 的终端按 Ctrl + C。

在别的设备上打开（手机 / 平板 / 另一台电脑）

服务默认监听 0.0.0.0（本机所有网卡），同一网络下的其他设备可直接访问，无需额外配置：

ipconfig        # Windows：找「IPv4 地址」，形如 192.168.x.x
ip addr         # macOS / Linux

# 在另一台设备的浏览器打开
http://192.168.x.x:3000

用 npm run demo 启动时，脚本会直接打印可用的局域网地址，不用自己查。

现象处理
连接被拒绝 / 超时Windows 防火墙拦截入站。管理员权限运行一次：netsh advfirewall firewall add rule name="webpilot" dir=in action=allow protocol=TCP localport=3000
手机能上网但打不开确认与电脑在同一个 Wi-Fi；部分公司/校园网开启「AP 隔离」，换手机热点即可
IP 变了路由器重新分配地址，重新 ipconfig 查一次
异地访问：局域网地址只在同一个网络内有效。要在别的地方打开，需要把服务部署到有公网 IP 的机器（见「17 部署」），或用内网穿透工具把 3000 端口映射出去。

推荐体验路径

  1. 输入「我这两天膝盖上下楼疼，想明天上午去医院看看，我叫张桂芳，身份证110105195003071234，手机13800138000」——观察口语症状如何经 RAG 映射到骨科，页面逐步自动填写；
  2. 到最后一步时界面会强制暂停并弹出授权卡，点确认后才会真正提交；
  3. 完成后回执卡片给出通俗播报，可点击朗读；
  4. 右上角切到「市民之家」，用同一套交互办医保缴费。

17 部署

两种形态按需二选一：静态站点（npm run build:static，产物 out/，放哪都能用 http 打开，不需要 Node 服务）与服务端应用（npm run build + npm run start，带 /api/* 接口）。

静态站点（推荐先试，不需要服务器）

npm run build:static     # 产出 out/ 目录（约 1.4 MB）

产物结构：out/index.html（主控台）、out/elder/index.html（适老挂号页，含语音助手 ai.js）、out/elder/standalone.html（单文件版，手机端最稳）、out/sim/city-hospital/index.html、out/sim/citizen-hall/index.html、out/_next/static/（脚本与样式）。

打开方式：把 out/ 整个目录作为站点根目录上传到任意静态空间（对象存储静态托管 / nginx / 内网文件服务器等），或本地 cd out && python -m http.server 8080 预览，也可以直接双击 out/index.html。

产物路径已全部相对化

Next 静态导出默认写 /_next/... 这类以斜杠开头的绝对路径，只有把 out/ 放在域名根目录才能打开，放到二级目录或直接双击打开会整页白屏、被代驾站点的 iframe 也加载不出来。构建时由 scripts/fix-static-paths.mjs 按每个页面的目录深度改写成相对路径（本次 42 处），因此 file:// 与任意二级目录都能正常打开。

静态形态能力不打折

引擎本来就是纯 TypeScript 实现，静态形态把它放到浏览器里跑（lib/runtime/），与服务端形态共用同一份 runAgent，事件序列完全一致。代驾流程、授权门禁、脱敏、审计、能力语义检索、防幻觉闸门、轨迹回放全部保留；没有 /api/*，因此 MCP 清单改为浏览器内调用同一份 lib/mcp/core，自动化评测改为打开页面即跑的「浏览器内自检」（5 场景 / 12 断言）。也不需要任何模型密钥——浏览器里取不到 LLM_API_KEY，自动走规则引擎，离线可完整演示。

本机生产模式

npm run build     # 生产构建
npm run start     # 生产模式启动，默认 :3000

服务器 / 云主机（服务端形态）

npm install
npm run build
npm run start:cloud    # scripts/start-cloud.mjs
三个部署要点
  1. start:cloud 由 Node 读取 PORT 后传给 next start -H 0.0.0.0，不依赖 shell 展开 $PORT——部分托管环境不展开，直接写 -p $PORT 会启动失败；
  2. 构建放在安装/准备阶段，不要放在启动阶段，否则可能吃掉健康检查的超时窗口；
  3. 未配置模型密钥时自动走规则引擎，部署后不依赖任何第三方可用性。

环境变量

生产环境建议显式设置 LLM_API_KEY、LLM_BASE_URL、LLM_MODEL、REQUIRE_HUMAN_CONFIRM=1。密钥只走环境变量，仓库内只有 .env.example 模板。
