## 二、把「文档排版」变成可断言的：`npm run check:docs`

这类问题改的时候不会报错，只会"看着乱"，而且下次改文档还会再犯。所以加了一个自检脚本 `scripts/check-docs.mjs`（`npm run check:docs`）：

- **HTML 标签栈**：逐标签入栈出栈，跳过 `script` / `style` 内部与注释，报出未闭合的标签及其行号 —— 就是这次第 1 条的根因；
- **h2 编号连续**：必须 1、2、3… 依次递增，重号 / 跳号 / 倒序都点名；
- **目录锚点**：`href="#xxx"` 必须能找到对应的 `id`，缺一个就报错；
- **目录顺序**：目录里锚点的排列顺序必须与正文中章节出现的顺序一致；
- **Markdown 同级编号**：逐级检查同级标题，支持中文数字（一、二…）与 `X.Y` 子编号，重复编号直接报错。

脚本只做静态检查、零依赖，跑一遍不到一秒。当前结果：**9 个文档、7 项检查全部通过**。

## 三、顺带修掉：窄屏下整页横向溢出

用真实浏览器在 390px 视口量文档站，发现 `scrollWidth - clientWidth = 35` —— 表格撑破了页面，整页能左右拖。原因是 `table { width:100% }` 在窄屏仍按内容最小宽度排，列宽压不下去。

改法是在 ≤860px 断点里让**表格自己横向滚动**，而不是让整页滚：

```css
@media (max-width:860px){
  nav{display:none}
  main{padding:20px}
  /* 窄屏下表格自己横向滚动，不让整页跟着溢出（整页溢出会把目录与正文一起推出屏幕） */
  table{ display:block; overflow-x:auto; -webkit-overflow-scrolling:touch; }
}
```

先浏览器里试了两种方案（`display:block + overflow-x:auto` 与 `table-layout:fixed + overflow-wrap:anywhere`），两者都能把溢出降到 0；选前者是因为它保留表格原本的列宽，读起来更顺，只是多一条内部滚动条。

排查过程中的两个环境坑，记下来免得再踩：

- **无头 Chrome 会读系统代理**：环境里有 `HTTP_PROXY`，不加 `--no-proxy-server` 的话连 `127.0.0.1` 都会走代理，页面直接打不开（症状是 `document.title` 返回主机名、选择器什么都选不到，很像"页面是空的"）。
- **file:// 路径里的中文**：必须百分号编码；更省事的做法是把要验的页面复制到一个纯 ASCII 路径下再打开。
