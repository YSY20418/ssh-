## 二、把「文档排版」变成可断言的：`npm run check:docs`

这类问题改的时候不会报错，只会"看着乱"，而且下次改文档还会再犯。所以加了一个自检脚本 `scripts/check-docs.mjs`（`npm run check:docs`）：

- **HTML 标签栈**：逐标签入栈出栈，跳过 `script` / `style` 内部与注释，报出未闭合的标签及其行号 —— 就是这次第 1 条的根因；
- **h2 编号连续**：必须 1、2、3… 依次递增，重号 / 跳号 / 倒序都点名；
- **目录锚点**：`href="#xxx"` 必须能找到对应的 `id`，缺一个就报错；
- **目录顺序**：目录里锚点的排列顺序必须与正文中章节出现的顺序一致；
- **Markdown 同级编号**：逐级检查同级标题，支持中文数字（一、二…）与 `X.Y` 子编号，重复编号直接报错。

脚本只做静态检查、零依赖，跑一遍不到一秒。当前结果：**9 个文档、7 项检查全部通过**。

## 三、顺带修掉：窄屏下整页横向溢出

用真实浏览器在 390px 视口量文档站，发现 `scrollWidth - clientWidth = 35` —— 表格撑破了页面，整页能左右拖。原因是 `table { width:100% }` 在窄屏仍按内容最小宽度排，列宽压不下去。

改法是在 ≤860px 断点里让**表格自己横向滚动**，而不是让整页滚：

```css
@media (max-width:860px){
  nav{display:none}
  main{padding:20px}
  /* 窄屏下表格自己横向滚动，不让整页跟着溢出（整页溢出会把目录与正文一起推出屏幕） */
  table{ display:block; overflow-x:auto; -webkit-overflow-scrolling:touch; }
}
```

先浏览器里试了两种方案（`display:block + overflow-x:auto` 与 `table-layout:fixed + overflow-wrap:anywhere`），两者都能把溢出降到 0；选前者是因为它保留表格原本的列宽，读起来更顺，只是多一条内部滚动条。

## 五、语音"点了没反应"——根因不是一处，是四处

现象：「点了语音，我说话，一点反应都没有。」

拿真实 Chrome + CDP 把整条链路拆开测，发现四个叠在一起的问题：

| # | 问题 | 表现 | 根因 |
| --- | --- | --- | --- |
| 1 | `speech.js` 压根没接进页面 | 离线入口永远不出现 | 上一轮写了模块，忘了在 `index.html` 里加 `<script src="speech.js">` |
| 2 | 浏览器自带识别的 `onend` 静默回流 | "正在听您说…"挂了 5 秒然后悄悄变回中性提示 | `rec.onend` 把没识别到结果当成正常结束，没跟老人说一句话 |
| 3 | 库的加载形态错了 | `Uncaught SyntaxError: Cannot use 'import.meta' outside a module` | `@huggingface/transformers` 的浏览器构建是 **ESM**，用普通 `<script src>` 加载必然语法报错 |
| 4 | 模型源不可达 / 跨域 | `net::ERR_FAILED` / CORS 报错 | 单源写死，且 `huggingface.co` 在国内容器里基本连不上 |

### 改法

**双链路，谁可用用谁。** 离线引擎（`public/elder/speech.js`）优先；浏览器自带的 Web Speech API 退为备用。

- **动态 `import()` 而不是 `<script>`**：ESM 包只能用 `import()` 取回来。好处是失败会被 `catch` 住，能交给上层回落；`<script type="module">` 的失败是无处可接的。
- **模型源顺序探测**：`config.json` 挨个试，谁先通就用谁（国内镜像 → 官方源），都通不了就如实说"没装成"，而不是假装在听。可用 `?asrHost=` / `localStorage` 覆盖，内网部署或把整套识别夹带在 U 盘里时用得上。
- **wasm 目录跟着库地址走**：onnxruntime 的 wasm 默认从库自己的 CDN 取。换了库地址却不换 wasm 目录，会出现"库在本地、wasm 还往外网要"。
- **上限计时（watchdog）**：开始听之后 12–25 秒没结果就主动收尾并说一句话。老人最怕的不是听错，是**点了没动静**。

## 六、把"失败"和"幻听"都当一等公民

Whisper-tiny 遇到环境音会**幻听**。真实浏览器实测（假麦克风=一段蜂鸣）拿到过两种输出：`好` 和 `（音樂）`。这不是偶发，是小模型的固有行为，必须专门处理。

两层处理：

1. `speech.js` 的 `clean()`：先剥掉模型给整句套的括号引号（`（音樂）`→`音樂`），再拿原始串与剥壳串**都**去撞幻听清单（`谢谢观看` / `字幕由…` / `请不吝点赞` / 单一字重复三次以上…），命中就返回空串；
2. `ai.js` 的 `hear()`：识别结果若是**一两个字且规则引擎认不出**（`understand('好')` → `unknown/score 0`），就当环境音处理，回"没有听到声音，请再说一次"，**不执行任何动作**，也**不说"没听明白"**——那会让老人以为自己说错了。

同时把交互闭环补齐：

- 云端还在听的时候点「用离线识别」也要有反应：先停掉云端，再开始装；
- 主动停下时状态栏回到待办提示，不让"正在听您说…"挂在那里骗人；
- 第二次打开（模型已在缓存里）时，**先装配好再开始听**，避免"第一次点了没反应、第二次才行"这种最劝退的体验。

## 七、方案选型：为什么最终是「transformers.js + Whisper（浏览器内）」

拿到过一份候选清单（Vosk / Whisper 系 / YazSes / local-stt / Turbo Whisper / Lipwise / Vocalinux / Handy / Speechfire / 讯飞 API / Puter.js / MurmurAI / WhisperLiveKit），按本项目的三条硬约束筛：**双击就能打开、零后端零密钥、失败必须有兜底**。

| 类别 | 代表 | 判断 |
| --- | --- | --- |
| 桌面成品软件 | YazSes / local-stt / Turbo Whisper / Lipwise / Handy / Vocalinux | ✗ 是独立的装机软件，没法嵌进网页里替老人点页面 |
| 浏览器扩展 | Speechfire | ✗ 要求老人先装扩展，且只做"往输入框里打字"，与本项目的"只走能力清单执行"不同路 |
| 自托管服务 | MurmurAI / WhisperLiveKit | ✗ 需要一台服务器，破坏"零后端 + 双击打开" |
| 免费云 API | 讯飞听写（500 次/天）/ Puter.js | △ 能用，但要联网、要配额，录音要出门，且违反"零密钥"；只适合当第三备选 |
| **浏览器内 WASM** | **transformers.js + Whisper ONNX 量化版** | **✓ 选定** |
| 浏览器内 WASM | vosk-browser | △ 同样离线，但项目维护活跃度低、中文模型约 42 MB 而精度不占优；API 与页面其它部分也更难对齐 |

选定的理由，逐条对上项目约束：

- **零后端零密钥**：模型是公开权重，库走 CDN，不需要任何账号；
- **断网可用**：模型装进本机缓存后，第二次打开连网都不用；
- **录音不出设备**：对适老医疗场景是实打实的加分项，不是噱头；
- **失败可回落**：`prepare()` 是 Promise，装不上就是装不上，页面照旧能点——这正是本项目"双链路兜底"原则的延伸；
- **`?asrLib=` / `?asrHost=`**：内网部署或离线夹带时可以把库与模型都指到自己的副本上。

代价也如实记下：模型约 41 MB（`whisper-tiny`），首次要下载；识别走 WASM 单线程，一段 10 秒的话大约要等几秒。所以文案里明确写了"第一次要下载一点点，装一次就行"，并且**这件事必须由老人自己点**才发生——不偷偷下载 41 MB。

## 十、「太杂乱，手机和网页的格式尺寸都不对」——视觉系统重做

用户原话：*"这几个页面都太杂乱了，一点都不美观，我这个是看的手机端的，网页端的也是，格式和尺寸都不对，自适应"*，并附了五张参考图：两张是当时的移动端截图，三张是成熟站点（新闻详情页、医生列表、患者端科室选择）。

**自适应是真问题，不是摆设。** 三处硬伤：

- **步骤条**：6 个胶囊横排，390px 下每个都被压成一条缝。<700px 改成「走过的步骤只留一个勾，当前步骤才显示名字」——信息量不减，宽度立刻够用。为此给 `renderStepbar()` 的 label 加了 `stepbar__label` 类（窄屏由 CSS 折叠，DOM 结构不变，42 项自检无需改编号）。
- **桌面端太空**：主内容一张大白纸 + 右栏，选项全部单列。改成选项网格化（症状 / 日期 3 列，医生 / 就诊人 / 付款 2 列），≥1440px 四个智能体并成一排。
- **英文模式整页横向溢出 17px**：这个bug 是查布局时意外逮到的。根因是 `.topbar__tools` 在 ≤480px 写死了 `flex-wrap: nowrap`，而英文语言标签（Simplified / Traditional / English）比中文长一倍，语言切换组 248px 宽塞不进去。修法两层：① 允许换行做兜底；② 按国际通行的「语言自称」写法把英文模式标签改成 简体 / 繁體 / English——既短，也不会在简体 / 繁体界面里混进英文单词。

顺带修了一个**隐性的顶栏撑高**：`.brand__text`（小鱼兒 / 網頁代駕）被 flex 收缩压到 47px 宽，四个字换行，顶栏从 41px 涨到 77px。根因是名字区和院名区都在抢宽度。改成**名字区 `flex: 0 0 auto` 不参与收缩，院名区负责让位**（它有省略号兜底），顶栏回到 41px，简 / 繁 / 英三语都是 120px。

悬浮球也收窄了：≤899px 从"鱼 + 跟我说话"药丸改成**圆形鱼标**。理由是参考图里没有这种东西，而带文字的药丸会实打实压住下面的选项卡片——对老人来说，「挡住能点的东西」比「少两个字」糟得多。文字改由 `aria-label` 供读屏识别（`renderTexts()` 里同步设置）。

## 十一、「麦克风始终不能被录入」——先查权限 API，再修错误分类

用户反馈：*"麦克风在网页始终不能被录入，检查麦克风权限api是否开启"*。

**先证伪，再修。** 没有急着改代码，而是用真实 Chrome + CDP 在三种打开方式下各量一遍：

| 打开方式 | `navigator.mediaDevices` | `getUserMedia` | 结论 |
| --- | --- | --- | --- |
| `file://` 双击单文件版 | 存在 | 成功（假设备） | API 是开的 |
| `http://127.0.0.1` 本地服务 | 存在 | 成功 | API 是开的 |
| 云端托管页（https） | 存在 | 成功 | API 是开的 |

**"API 没开"是误判。** 真正的病根是：用户（或系统设置）把麦克风权限置成了"阻止"——浏览器对这种状态**不会再弹第二次窗**，于是每一次点击都失败、每一次都只说一句笼统的"没能打开麦克风，请再点一次"。再点一百次还是被拒，老人被困死在循环里，这就是"始终不能被录入"的体感。

用 `Browser.setPermission` 把权限设成 DENIED 实测，确认了错误码：`getUserMedia` 抛 `NotAllowedError`；而 `navigator.permissions.query` 在这种策略禁用下仍返回 `prompt`——**所以权限查询 API 只能用来"提前告知"，不能拿来拦人**，真正拍板必须靠 `getUserMedia` 抛出的错误名。

### 改法：真实尝试 → 按码说话 → 给得出恢复指引

1. **`speech.js`**：新增 `micState()`（`permissions.query` 包装，返回值 `granted / denied / prompt / unsupported`）；`Recorder.start()` 先自检 `navigator.mediaDevices` 是否存在（`file://` 被禁时整个接口会消失），再把浏览器的错误名归一成五类——`NotAllowedError→denied`、`NotFoundError→no-device`、`NotReadableError→busy`、`SecurityError→insecure`、`OverconstrainedError→no-fit`，reject 出带 `code` 的 Error。
2. **`ai.js`**：面板常显一行**麦克风状态**（已允许 / 被拦住 / 还没问过 / 查不出来），每次停下都重新读一次（老人可能刚在浏览器里改过设置）；失败时按码说人话，被拦住就展开**三步恢复指引**（点地址栏左边小图标 → 找到「麦克风」行 → 改成允许）+「再试一次麦克风」实心按钮。**顺序上坚持先按老人的点击真实试一次**——先查权限再拦截会让按钮"点了没反应"，退回老问题。
3. **两条链路答案一致**：云端 `SpeechRecognition` 的 `not-allowed` 与离线链路的 `denied` 合并成同一套话术与指引（删掉不再使用的 `ai.denied`，三条语言各一份）。

### 一个差点漏掉的细节

第一次真实浏览器复测时，面板里显示的仍是**旧文案**——因为无头环境没装过离线识别，点击走的是**云端 SR 链路**，它的 `onerror` 分支还挂着旧的 `ai.denied`。也就是说：离线链路修好了，云端链路没跟上，两条路给老人的答案不一致。已合并。**这类"只修了一条链路"的 bug 在双链路设计里特别常见**，值得在 checklist 里常驻。

## 十三、「只会简单对话」——本地语料库 + 千例对话沙盒测试

用户反馈两件事：① 话术里「65 岁以上」是年龄限制，有些沟通障碍的人也能用，改成「为长者服务」；② 截图里语音助手对「然后我应该干嘛？」只会回「没听明白。您可以这样说：」，翻来覆去还是这一句——**只会简单对话，不会多语言对话**。要求：沙盒测试不少于一千种对话都能识别并快速回复，并把代码过程、实现依据、素材来源、环境配置、智能体做法、话术训练方法、本地数据库都写下来。

### 先治病根：一句话过四道关，对话层排在最后

`understand()` 的顺序就是优先级：确认窗开着只听确认取消 → 页面控制命令（念 / 停 / 字号 / 前后步）→ 业务动作（症状 / 科室 / 医生 / 时间 / 付款）→ **都不命中才进对话层**。反过来会出事故：老人说「我要挂号」却被回一句问候、页面纹丝不动。对话层的匹配结果在函数开头就算好备用，有两个用处：收尾时兜底，以及**让「专家号」这类既是科室泛称又是常见咨询的词把问诊提醒让位给真问答**（否则问「专家号贵吗」得到的是「您主要是头晕还是咳嗽」）。

### 本地数据库：话术是数据，不是代码

新建 `data/corpus.json`（纯 JSON，file:// 下 fetch 会被拦，所以必须编译成 `<script src>` 能加载的 JS）→ `scripts/build-corpus.mjs` 校验并生成 `public/elder/corpus.js`（数据 + 匹配器，挂 `window.XiaoYuErCorpus`）。27 个意图、**3929 条说法**（zh 1660 / zh-Hant 1637 / en 632），覆盖打招呼、问身份、问能耐、步进指引、道谢道别、诉说难受、危急劝导、九个挂号 FAQ、陪聊解闷等。

匹配算法五步：归一（小写 + 去标点，中文不分词所以靠子串）→ **最长说法赢** → 平手看 priority → 语言跟随（先当前界面语言，找不到再找另外两门，所以英文界面说中文用中文回）→ 回复轮换（每意图 2–3 条，不复读）。

**guide 意图**按当前步骤回答：第 0 步教开始、第 1 步教说症状、第 4 步教选人就付款——这正是截图里没人答的那一问。

### 数据库的五条硬规则（构建时质检，不过就退出非零）

1. 每个意图三语齐全，说法与回复非空；
2. guide 意图必须给出全部六个步骤的话术；
3. **同一语言下任何说法只能属于一个意图**（消歧义）；
4. 说法不能归一化成空串；
5. 回复里只允许 `{step}` `{name}` 两个占位符。

第一轮校验就逮到 33 处问题：12 处占位符误报（校验器自己的 bug）、21 处跨意图重复（「转院」同时挂在证件和取消下、「发票」挂在三个 FAQ 下……）。全部按「留更贴切意图」清掉。

### 一个隐蔽的坑：说法会和页面命令关键词撞车

语料说法如果是命令关键词的**子串**，会被命令层抢先，FAQ 永远答不上：「下一步做什么」含「下一步」→ 被当成翻页；「谢谢你帮忙」含「帮忙」→ 被当成需要帮助；「明天见」含「明天」→ 在第 3 步被当成选日期；「停一下」含「停」→ 被当成停止朗读。处理办法分两种：改说法（删掉命令词），或接受命令行为（「家属挂号」被当成开始挂号，结果也是对的）。共清理 86 条。**这类撞车在双链路上特别隐蔽**，已固化成自检第 47 项（`ai.understand('我腿疼').intent === 'act'`）。
