# 开发日志 · 2026-10-13

## 一、修复：手机上打开适老挂号页中文乱码

### 现象
电脑打开完全正常，手机打开后中文全是乱码。

### 根因（实测）
文件本身是 UTF-8、`<meta charset>` 也写对了，但常见静态服务器对三类文件都**不带 charset**：

```
/index.html   → Content-type: text/html
/app.js       → Content-type: text/javascript
/styles.css   → Content-type: text/css
```

HTML 还能靠 `<meta charset>` 自救；**外链的 JS / CSS 没有任何编码线索**，只能靠 HTTP 响应头或文件 BOM。
`app.js` 有 3213 个汉字、`ai.js` 有 2979 个，手机浏览器（国产内核）会按系统默认编码 GBK 解析 → 全乱。

### 四层修复
| 层次 | 做法 |
| --- | --- |
| HTML | 补 `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` 兜底 |
| 外链 | `<link>` / `<script>` 显式写 `charset="utf-8"` |
| CSS | 文件首行 `@charset "UTF-8";` |
| JS | 文件加 UTF-8 BOM（外链脚本唯一的编码线索） |

### 根治：单文件版
新增 `scripts/build-elder-single.mjs`，`npm run build:elder` 生成 `public/elder/standalone.html`
（样式与脚本全部内联，带 BOM，可单独传到手机打开）。
内联时注意三点：剥离 CSS 的 `@charset`、转义 `</script>` 与 `<!--`、读文件用 utf-8-sig 吃掉 BOM。

### 顺带新增
`scripts/serve-static.mjs`（`npm run serve:static`）：零依赖静态服务器，所有文本响应强制带
`; charset=utf-8`，启动即打印局域网地址与防火墙放行命令，方便用手机直接验收。

## 二、适老挂号页视觉与自适应优化

### 需求核实（与用户逐条确认）
| 项 | 结论 |
| --- | --- |
| 色彩方向 | 保留暖米白体系（#F2F0EA / #2F5D62 / #FAF3E4），只提对比与层次，不换主色 |
| 医院名称 | 使用虚构名「示范市人民医院」，页面不得出现任何现实医院名 |
| 自适应重点 | **电脑优先**：宽屏做专门布局，窄屏等比缩放兜底 |
| 素材来源 | Pixso 社区素材（纯前端渲染，需浏览器才能读取；本轮尚未并入） |

### 设计决策
1. **三主色不动**。`check-elder.mjs` 里有「配色符合要求」的硬断言，改主色会直接破自检；
   层次感改由背景分层、阴影、选中态、顶部渐变条来承担。
2. **宽屏双栏**。≥1024px 采用「左流程 + 右常驻摘要」，主内容再包一层白纸卡片 ——
   老人随时能在右栏看见「已经选好的：症状 / 科室 / 医生 / 时间 / 付款」，不用往回翻。
3. **背景只用抽象图形**。医院氛围用内联 SVG 绘制（楼宇轮廓 + 十字 + 心电线），
   opacity 0.06，**不含任何 `<text>`**，既满足「像医院」又不指向任何真实机构。

### 实现要点
- `styles.css` 整体重写：新增 `--shell`（1160px，超宽屏 1240px）、`--shadow-lift` 加强、
  `--ink` / `--ink-2` / `--muted` 加深；`body::before` 承载背景 SVG。
- 断点体系重做：`480px`（窄屏等比兜底）/ `700px`（平板并排）/ `1024px`（电脑双栏）/ `1440px`（超宽）。
- 新增 `.shell` / `.flow` / `.aside` 结构；顶部品牌区加院名（简繁英三语）。
- `app.js` 新增 `renderAside()`；`call()` 的成功返回统一刷新右栏 ——
  因为点选走的是就地更新（不重建 DOM），不会触发 `renderStep`。
- 回执卡片顶部显示院名。

## 三、手机端适配打磨与渲染容错（同日续）

### 起因
上一节的视觉优化是「电脑优先」，手机端只做了等比兜底。这次把手机端逐屏核对，顺手引入**真实设备视口**的自检能力：命令行 `--window-size` 在 Windows 上有最小窗口宽度限制（实测请求 390px 只能拿到 489px 视口，截出来的图右侧还会被裁，容易误判成「页面溢出」），改用 CDP 的 `Emulation.setDeviceMetricsOverride` 才能得到真实手机视口。

### 查出并修掉的问题

| # | 问题 | 实测证据 | 修法 |
| --- | --- | --- | --- |
| 1 | 悬浮的「跟我说话」按钮压住底部「需要帮助」按钮 | 390×844 下重叠 55px（悬浮按钮 639–711，操作栏 656–844） | 新增 `syncActionbar()` 把操作栏实际高度写入 `--actionbar-h`，悬浮按钮按它动态避让；修后间距 17px，重叠消失 |
| 2 | 手机端顶栏固定占 223px（品牌行 + 字号行 + 语言行共三行），一屏近 1/3 被固定区吃掉 | 顶栏 223px + 步骤条 73px = 296px | 窄屏下压缩内边距、字号与控件尺寸，工具组占满一行左右分布；修后 **124px**，省下 99px |
| 3 | 状态不全时进第 4 步直接抛错，整页渲染中断（付款方式整块空白、右栏不更新） | `Cannot read properties of undefined (reading 'name')` —— `renderSummary()` 读 `DEPTS[state.dept].name`、`stepVoice()` 读 `DEPTS[state.dept].name` 与 `currentDoctor().name` 都没做空值防御 | ① 摘要与播报文案改为空值友好的占位符；② 各步渲染用 `safeRender()` **分块隔离**，单块出错不再拖垮整页 |
| 4 | 语言切换器在中文界面显示 `English`，违反「界面不出现英文」的硬约束 | 简体模式下可见文本含 `English` | 标签改为随语言切换的三套文案：中文两套显示「简体 / 繁體 / 英文」，英文模式显示 Simplified / Traditional / English |

### 无头浏览器自检的注意点
- Windows 上 Chrome `--window-size` 有最小宽度（实测约 489px），窄屏必须走 CDP 设备模拟，否则会得出「页面横向溢出」的错误结论。
- `--dump-dom` 配合 `document.title` 回写诊断结果是可行的轻量做法；但 `setTimeout` 延时执行的内容要在虚拟时间预算内，否则 dump 拿不到。
- 若页面有 `position: fixed` 元素，整页截图（`captureBeyondViewport`）会把它们画在视口位置而非文档流位置，看起来像「遮住内容」——那不是 bug，要按数值判断而不是看图。
