## 一、代码形态：纯 ES5、零依赖、零构建

**为什么是纯 ES5**：适老页的第一约束是「双击就能开」。老人拿到的可能是一个文件、一个 U 盘、一次微信转发，没有一个 `npm install` 的时刻。所以页面不能依赖任何框架、任何打包器、任何 CDN——四个脚本（`icons.js` / `app.js` / `speech.js` / `corpus.js` / `ai.js`）用 `<script src>` 顺序挂载，全部是普通函数式 ES5，连 `let` / 箭头函数都没有。

**为什么不直接 `fetch('corpus.json')`**：`file://` 协议下浏览器会把本地 fetch 当跨域请求拦掉，双击打开的页面拿不到数据。所以数据库必须**编译成 JS 文件**（`npm run build:corpus`），这是整个项目里唯一一道「构建」工序，而且它零依赖——一个 Node 脚本，读 JSON、校验、吐 JS。

| 文件 | 职责 | 能不能手改 |
| --- | --- | --- |
| `data/corpus.json` | **本地对话数据库**：意图 → 三语说法 → 回复话术 | 能，这是唯一要改的文件 |
| `scripts/build-corpus.mjs` | 校验数据库（5 条硬规则）→ 生成 `corpus.js` | 能 |
| `public/elder/corpus.js` | 编译产物：数据 + 匹配器，挂 `window.XiaoYuErCorpus` | **不能**，改了会被覆盖 |
| `public/elder/ai.js` | 决策层：把一句话变成动作或一句话回复 | 能 |
| `public/elder/speech.js` | 识别层：浏览器内 Whisper + 自带识别，双链路 | 能 |
| `public/elder/app.js` | 页面本体：五步流程、三语文案、能力清单 | 能 |
| `scripts/check-corpus.mjs` | 沙盒测试：几千条对话逐条灌进匹配器 | 能 |

**编码四层防护**（这是踩过坑固化的）：HTML `http-equiv` + `<meta charset>` 双声明 → 外链 `<script charset="utf-8">` → CSS 首行 `@charset` → JS 文件带 UTF-8 BOM。根因是外链脚本没有编码线索时，部分手机内核按 GBK 解析。单文件版 `standalone.html` 全内联，编码只由 `<meta charset>` 决定。

## 二、实现依据：一句话的旅程

老人说出一句话后，代码按**固定顺序**过四道关。顺序即优先级——越靠前越先说话，这样「能办的事」永远优先于「闲聊」。

```
一句话
  │
  ├─ ① 确认窗开着？ ──是──► 只听「确认 / 取消」，别的都不动（高危动作的闸门）
  │
  ├─ ② 页面控制命令？ ──是──► 念一遍 / 别念了 / 字大点 / 上一步 / 重新挂……
  │                        （改页面，一句话只做一件事）
  │
  ├─ ③ 业务动作？ ──是──► 症状 / 科室 / 医生 / 日期时段 / 就诊人 / 付款 / 提交
  │                        （改页面，取值只能来自当前可选项）
  │
  └─ ④ 都不命中 ──► 对话层：本地语料库 XiaoYuErCorpus.match()
                        打招呼 / 问身份 / 问能耐 / 步进指引 / 道谢道别 /
                        诉说难受 / 危急劝导 / 挂号 FAQ / 陪聊解闷……
                        只回话，不动页面
```

### 匹配算法（`corpus.js` 里的 `match()`）

1. **归一**：小写 + 去空白和标点。中文不分词，所以匹配的基本单位是「说法是不是句子的子串」——这也正是它能扛住同音错字和口语的原因（`挂个骨科`、`我腿疼`、`腿疼得厉害` 都含 `腿` 相关说法）。
2. **最长说法赢**：所有意图里找出最长的那个命中说法。所以「专家号贵吗」命中 `专家号贵吗`（faq_free）而不是 `专家`（科室泛称）。
3. **平手看优先级**：长度一样时，`priority` 数字小的意图赢（`emergency` 是 5，最先被考虑）。
4. **语言跟随**：先按当前界面语言找，没找到再找另外两门——所以英文界面里说中文，会用中文回你（见自检第 46 项）。
5. **回复轮换**：每个意图备 2–3 条回复，轮着说。连问八次「你好」不会得到八句一模一样的话——老人对复读机的忍耐度是零。

### 为什么命令必须排在对话前面

反过来会出事故：老人说「我要挂号」，如果对话层先接，就可能回一句「您好！我是小鱼儿……」而页面纹丝不动——那正是最初被反馈的问题。现在的顺序保证：**凡是能办的事，一定办；办不了的，才陪您聊。** 自检第 47 项专门守这条（`ai.understand('我腿疼').intent === 'act'`）。

### 执行层：决策与执行分离

智能体只输出「意图 + 参数」，真正的点击由确定性代码完成：

- **能力清单** `XiaoYuEr.call(id, params)`：9 项标准能力（选症状 / 选科室 / 选医生 / 选日期 / 选时段 / 选就诊人 / 选付款 / 提交 / 朗读），参数越界一律拒绝——说一个页面上没有的选项会被挡回来；
- **导航白名单** `XiaoYuEr.nav(cmd)`：只有 12 个命令（下一步 / 上一步 / 帮助 / 念一遍 / 停止 / 确认 / 取消 / 字号…），语音碰不到白名单以外的东西；
- **步骤闸门** `STEP_GUARD`：选医生只能在第 2 步、付款只能在第 4 步——在错误步骤上说话不会乱点页面；
- **高危授权**：说到「确认预约」只把确认窗**叫出来**，提交必须本人点绿色按钮或本人说「确认」。

## 四、环境从哪里配置

**运行环境**：Node 20+（开发用，页面本身不需要）。脚本全部零依赖，只有自检 `check-elder.mjs` 需要 jsdom（装在上级 `.build-trash/node-tools`）。

| 命令 | 干什么 | 什么时候跑 |
| --- | --- | --- |
| `npm run build:corpus` | 校验 `data/corpus.json` → 生成 `public/elder/corpus.js` | **改完语料库必须跑** |
| `npm run check:corpus` | 沙盒测试：全部说法 + 装饰变体逐条识别 + 测速 | 改完语料库必须跑 |
| `npm run check:elder` | 全栈自检（jsdom）：48 项断言，含对话链路 | 改任何页面代码后跑 |
| `npm run check:docs` | 文档结构自检：标签闭合 / 编号连续 / 目录锚点 | 改文档后跑 |
| `npm run build:elder` | 生成单文件版 `standalone.html`（样式脚本全内联） | 交付 / 发布前跑 |
| `npm run serve:static public -p 8794` | 起本地服务看页面 | 随时 |

**沙箱注意事项**（都是踩过的坑，写进记忆备查）：

- npm 必须带 `--registry=https://registry.npmjs.org`（淘宝源会 403）；
- `next build` 在沙箱里写 `.next/trace` 会 EPERM，验证用 `tsc --noEmit` + dev/curl；
- curl 本地服务加 `--noproxy '*'`；Windows 无头 Chrome 要加 `--no-proxy-server`；
- 沙箱会**回收脱离命令的后台进程**，起服务必须用受管后台任务，否则探针报 `ERR_CONNECTION_REFUSED`，极易误判成「页面打不开」；
- `serve-static.mjs` 默认服务 `out/`（旧构建），看最新改动要显式传 `public`。

## 五、智能体是怎么搭的

**分工**：四个智能体，各自一句话职责——聽懂您的話（识别）/ 替您一步步辦（执行）/ 替您把好關（安全）/ 把結果講給您聽（播报）。

**接线方式**：

```
麦克风 ──► speech.js（双链路：浏览器内 Whisper 优先，自带识别兜底）
              │  两条路都有 watchdog：云端 12 s / 离线 25 s 没结果就主动开口
              ▼
           一句话文本
              │
              ▼
           ai.js understand() ──► 命令层（改页面）│ 对话层 corpus.js（只回话）
              │
              ▼
           执行：XiaoYuEr.call() 能力清单 / XiaoYuEr.nav() 白名单
              │
              ▼
           播报：XiaoYuEr.speak()，语言跟随界面
```

**换真大模型**：挂一个决策函数即可——`window.XiaoYuErAI.setPlanner(fn)`。它返回动作序列就用；越权动作、抛错、返回不可解析，一律自动回落到规则引擎。**演示永不崩**是这个架构的硬约束。

**麦克风被拦**：权限查询 API（`navigator.permissions`）有的浏览器在策略禁用下也答 `prompt`，所以**只能用来提前告知，不能拿来拦人**——拍板必须靠 `getUserMedia` 抛出的真实错误名。错误名归一成五类（denied / no-device / busy / insecure / no-fit），被拦住时给出三步恢复指引 + 「再试一次麦克风」按钮。

## 六、话术工作流：怎么调教、怎么训练

**核心心法：话术是数据，不是代码。** 改话术 = 改 JSON，不用碰一行逻辑。

### 给语料库添一个新意图（五步）

1. **开 `data/corpus.json`**，在 `intents` 数组里加一段：
   ```json
   {
     "id": "faq_parking",
     "kind": "chat",
     "priority": 12,
     "note": "停车",
     "zh": {
       "patterns": ["能停车吗", "有停车场吗", "停车方便吗", "车位", "停车费"],
       "replies": ["医院里面有停车场，车位不多，建议早点到或者坐公交来。"]
     },
     "zh-Hant": { "patterns": ["能停車嗎", "有停車場嗎"], "replies": ["醫院裏面有停車場，車位不多，建議早點到或者坐公交來。"] },
     "en": { "patterns": ["parking", "can i park", "parking lot"], "replies": ["There is a parking lot on site, but spaces are limited — come early or take the bus."] }
   }
   ```
2. **跑 `npm run build:corpus`**——五条硬规则会替你质检：三语齐全、回复非空、guide 步步有话术、**同一说法不能属于两个意图**、回复里不许有未定义占位符。不过就退出非零，并指出是哪一条。
3. **跑 `npm run check:corpus`**——新说法立刻进入几千条对话的沙盒测试。
4. （可选）在 `ai.js` 的 `KW` 里给相关命令关键词加别名。
5. **提交**。

### 变体从哪里来（这是「识别率高」的秘密）

| 来源 | 例子 |
| --- | --- |
| 客气话 | 请问 / 麻烦 / 劳驾 / 不好意思 / 我想问一下 |
| 语气词与口语 | 呗 / 呢 / 啊 / 嘛 / 嘞 |
| 同音错字（语音识别高频错） | 一包→医保、夏午→下午、明田→明天、管好→挂号 |
| 方言口音 | 啥 / 咋 / 甭 / 得嘞 / 齐活 |
| 换着说法问同一件事 | 「多少钱」/「贵不贵」/「收费标准」/「要钱吗」 |
| 长短句 | 「退号」/「怎么取消」/「取消不了怎么办」 |

自检第 ③ 项会拿 13 个前缀 × 9 个后缀（请问 / 麻烦 / 可以吗 / 谢谢…）套在每条说法上再识别一遍——**老人不会照着词表说话**。

### 回复怎么写

- 短句，一次只说一件事；先给结论，再给办法；
- 行动导向：能点的告诉点哪，能说的告诉说什么；
- 不过度安抚、不堆感叹号；危急情况（`emergency`，优先级 5 最高）第一句永远是「先打 120」；
- 步进指引（`guide`）按当前步骤回答：第 0 步教开始、第 1 步教说症状、第 4 步教选人就付款——这正是最初被反馈「然后我应该干嘛？」没人答的那一环。

### 一条容易踩的线：别和页面命令撞车

语料说法如果是页面命令关键词的子串，会被命令层抢先（「下一步做什么」含「下一步」会被当成翻页）。发现办法：自检里对一句话的意图做断言。处理办法：改说法（去掉命令词）或接受命令行为（「家属挂号」被当成开始挂号，结果也是对的）。

## 七、本地语料库怎么用

### 数据长什么样

```json
{
  "version": "1.0.0",
  "meta": { "langs": ["zh", "zh-Hant", "en"], "steps": 6 },
  "intents": [
    {
      "id": "greet",            // 意图唯一 ID
      "kind": "chat",           // chat=闲聊问答；guide=步进指引
      "priority": 10,           // 平手时谁赢（数字小的赢）
      "note": "打招呼",
      "zh": {
        "patterns": ["你好", "您好", "哈喽"],     // 说法（命中即算）
        "replies": ["您好！…", "您好！…"]          // 回复（轮换）
      },
      "zh-Hant": { "patterns": [...], "replies": [...] },
      "en": { "patterns": [...], "replies": [...] }
    }
  ]
}
```

`guide` 意图没有 `replies`，换成 `steps`——六个步骤各一段话，可用占位符 `{step}` `{name}`：

```json
"zh": {
  "patterns": ["然后呢", "接下来做什么", "该干嘛"],
  "steps": {
    "1": "现在第 {step} 步（{name}）：您说说哪里不舒服，比如「我腿疼」「我头晕」，我替您选好。"
  }
}
```

### 当前规模

27 个意图、3929 条说法（zh 1660 / zh-Hant 1637 / en 632），覆盖：打招呼、问身份、问能耐、步进指引、道谢、道别、诉说难受、危急劝导、这是什么、费用、证件、取消改约、迟到过号、取号报告、替家人挂、开诊时间、支付方式、选医生科、等一下、再说一遍、夸奖、陪聊、界面困惑、年龄适老、说话不便、不用帮忙、听错了。

### 五条硬规则（`build:corpus` 质检）

1. 每个意图三语齐全，说法与回复都非空；
2. `guide` 意图必须给出全部六个步骤的话术；
3. **同一语言下，任何说法只能属于一个意图**（消除歧义，数据库卫生）；
4. 说法不能归一化成空串（纯标点是脏数据，永远匹配不上）；
5. 回复里只允许 `{step}` `{name}` 两个占位符。
