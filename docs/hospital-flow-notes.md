# 真实医院预约挂号流程 · 审核与提炼

> 目的：把真实医院网上预约挂号的流程规范，逐条对照成「小鱼儿」网页代驾可以执行的动作，
> 避免我们做的是「看起来像挂号」的演示，而不是真正能覆盖挂号全流程的代驾。

## 一、参考来源与审核方式

- 参考站点：某三甲医院官网（不指名，避免与真实机构对应）。其在线预约子页面已下线（返回 404），
  因此改为从其官网首页的就医入口（预约诊疗 / 预约挂号 / 门诊指南 / 科室检索 / 专科专家介绍 / 医保报销指引）
  与国内三甲医院通用的预约挂号规范进行交叉提炼。
- 审核口径：只保留**能落到「能力」上的**流程项；纯展示性内容（新闻、院史）一律不纳入。

## 二、提炼出的流程骨架（7 个环节）

| # | 环节 | 真实流程要点 | 落到代驾/适老页的做法 |
|---|------|--------------|----------------------|
| 1 | 就诊人 | 姓名、身份证/就诊卡、手机号；可以为本人或家属代约 | 常用就诊人卡片点选（本人/老伴/家人陪同）；身份证与手机号全程脱敏 |
| 2 | 科室 | 按症状或科室导航选择，常配「导诊/全科」兜底 | 症状 → 科室映射 + 备选科室可改挂；说不清时落到全科医学科 |
| 3 | 医生与号源 | 职称、擅长、挂号费、剩余号源；专家号与普通号区别 | 医生卡片（头像/职称/擅长/挂号费）；号源为 0 时置灰不可点 |
| 4 | 日期与时段 | 分上午/下午两段，可约未来数日，号满不可选 | 今天/明天/后天 + 上午/下午；约满置灰并提示换时间 |
| 5 | 付款方式 | 医保、微信、支付宝、到院窗口付 | 四种付款方式大卡片，老人没说时默认「到医院再付」（风险最低） |
| 6 | 凭证 | 取号码、就诊楼层与诊室、医生与时段 | 回执输出预约号、就诊地点（楼层·诊室）、时间与医生 |
| 7 | 到院须知 | 携带证件、提前到院、先分诊报到、可退改约 | 回执播报三条须知：带身份证 / 提前 15 分钟 / 先到一楼分诊台；另附退改约说明 |

## 三、对代驾引擎的具体改动（已落地）

`lib/sim/hospital.ts`：

1. 科室清单增加 **全科医学科**（老人说不清症状时的兜底），并新增 `DEPT_PLACE` 科室 → 楼层诊室映射；
2. 新增 `PAY_METHODS` 与 `guessPayMethod()`：医保卡 / 微信 / 支付宝 / 到医院再付，
   老人未说明时默认「到医院再付」，不阻塞流程；
3. 新增 `guessRel()`：本人 / 老伴 / 家人陪同；
4. 确认页新增「就诊人关系」「付款方式」两个能力，提交动作 `submitBooking` 的
   `requires` 增加 `payMethod`，提交前必须明确；
5. 回执新增 `location`（就诊地点）、`payMethod`、`arriveTips`（到院须知三条），
   并把「到院须知」放在回执第二行，保证老人第一眼看到；
6. 领域约束 `domainHints` 补充：时段约满需改选；付款方式取值范围。

## 四、对适老页的具体落地

`public/elder/`（纯静态，无框架）：

- 第 1 步 7 个症状大按钮 → 推荐科室，可「换个科室」；
- 第 2 步医生大头像卡片（职称 + 擅长 + 挂号费）；
- 第 3 步日期 + 上午/下午，约满置灰；
- 第 4 步核对信息（常用就诊人点选，身份证手机号脱敏）+ 四种付款方式；
- 第 5 步成功页：取号码 + 就诊地点 + 三条到院须知（带身份证 / 提前 15 分钟 / 先到分诊台）。

## 五、明确的非目标

- 不做真实支付、不对接真实医院 HIS 系统，所有数据均为演示用虚构数据；
- 不做登录注册、不做病历查询；
- 不做任何需要键盘输入才能完成的步骤。
