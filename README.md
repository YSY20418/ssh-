# 小鱼儿 · 网页代驾 Agent

> 说一句话，AI 替你把网页流程跑完。

面向银发群体的 AI Native Web 应用：老人用口语（或方言语音）说出需求，智能体在真实网页流程中自主完成挂号、填表、核对、提交等全部步骤；**涉及不可撤销的高危动作时强制停下，等待本人授权**。

**源码就在本仓库**：网页与接口在 `app/`，界面组件在 `components/`，引擎在 `lib/`。拉下来两条命令就能跑：`npm install` → `npm run dev`，浏览器打开 `http://localhost:3000`。完整步骤见「五、安装与运行」。

## 一、这个项目做什么

### 1.1 要解决的痛点

线上办事已经普及，但老年人面对的不是"没有服务"，而是三道坎：

- **流程太长**：挂号要选科室、选医生、选时段、填就诊人、核对提交，五步以上；
- **术语太多**：老人说"膝盖上下楼疼"，网页只给他一个"骨科 / 内科 / 外科"的下拉框；
- **不敢点错**：填错身份证、误触支付，后果不可撤销，于是干脆放弃。

已有的"适老版"方案大多只是把字号变大，交互范式没变——依然是人去适应网页。本项目反过来：**让 AI 去适应网页，人只需要说话。**

### 1.2 一句话定义

| 维度 | 常见 AI Web 产品 | 小鱼儿 |
| --- | --- | --- |
| AI 的角色 | 顾问：告诉你怎么做 | 代办者：直接替你做完 |
| 交互范式 | 人操作网页，AI 在旁边答疑 | 人说话，AI 操作网页 |
| 网页形态 | 为人设计的 DOM | 为人渲染，同时为 Agent 暴露**能力清单** |
| 风险控制 | 无 | 高危动作强制人工授权 + 全程审计 + 敏感值脱敏 |
| 兜底 | 模型不可用即不可用 | 大模型与规则引擎双链路，无缝降级 |

### 1.3 已接入的两个演示站点

| 站点 | 路由 | 场景 |
| --- | --- | --- |
| 市第一医院 | `/sim/city-hospital` | 预约挂号：选科室 → 选医生与时段 → 填就诊人 → 核对提交 |
| 市民之家 | `/sim/citizen-hall` | 医保 / 社保缴费：选参保类型 → 选年度与档次 → 填参保人 → 核对缴费 |

两个站点共用同一套 Agent、同一套安全裁决、同一个 MCP 工具层——新增站点只需写一份 `SiteDef`（见 3.3）。

### 1.4 给老人自己点的挂号页（纯静态）

除了「说一句话，智能体替你跑」之外，项目还单独做了一份**让老人自己点也能点完**的挂号页：

```
public/elder/index.html + styles.css + app.js     # 零框架、零依赖，双击即可打开
public/elder/icons.js                             # 29 个内联 SVG 图标（离线可用、零图片请求）
public/elder/ai.js + ai.css                       # 语音智能助手：说话就能替老人点
public/elder/standalone.html                      # 单文件版：样式脚本全内联，手机端最稳
```

| 要求 | 实现 |
| --- | --- |
| 只用点选，不出现键盘 | 全页 0 个输入控件（自检断言 01 覆盖），每一步都是大卡片点选 |
| 每步只做一件事 | 选症状 → 选医生 → 选时间 → 核对付款 → 成功页，5 步单任务 |
| 老人不会操作 | 底部常驻「上一步 / 需要帮助 / 下一步」；每步可「听语音提示」；提交前弹确认窗防误点；顶部 A- / 标准 / A+ 调字号并记忆 |
| 不刺眼的配色 | 背景暖米白 `#F2F0EA`、卡片纯白、主色深青绿 `#2F5D62`、提示区淡米黄 `#FAF3E4`，不使用高饱和纯黄纯红 |
| 字号与点击区 | 正文 19.5px、标题 29px、圆角 16px、按钮最小高度 64px，均支持整体缩放 |
| 三种语言 | 简体中文 / 繁體中文 / English，**文字与语音同步切换**（zh-CN / zh-TW / en-US） |
| 后续接智能体 | 页面对外声明 9 项标准能力（`window.XiaoYuEr.capabilities`），`call()` 只接受清单内动作，高风险提交必须 `granted: true` |
| 图形不认字也看得懂 | 每一步的选项、付款方式、到院提醒都配图标；29 个图标全部内联 SVG，只用页面主色，**不加载任何图片** |

自检：`npm run check:elder`（36 项断言，含完整点选流程、三语完整性、语音语言跟随、字号缩放、越权拒绝与高危授权、语音助手全链路、编码声明与单文件版、虚构院名与背景合规、自适应断点、右栏摘要联动、**中文界面无英文单词**、**数据不全也不崩**、**悬浮按钮不遮挡底部按钮**、**图标零图片请求且配色不越界**）。

## 三、技术架构

### 3.1 整体分层

```
┌──────────────────────────────────────────────────────────────┐
│ 老人（语音 / 口语 / 方言）                                       │
└───────────────┬──────────────────────────────────────────────┘
                ▼
┌──────────────────────────────────────────────────────────────┐
│ 主控台（Next.js 15 App Router + React 19 + Tailwind v4）       │
│  ├ 语音输入 Web Speech API / 语音播报 speechSynthesis          │
│  └ 执行轨迹可视化：思考 · 动作 · 观察 · 授权                     │
└───────────────┬──────────────────────────────────────────────┘
                ▼ SSE（自定义 Agent 事件流）
┌──────────────────────────────────────────────────────────────┐
│ 四智能体编排层（服务端 lib/agents/）                             │
│  Planner → Navigator → Guardian → Reporter                    │
│   ↳ RAG 办事指南检索   ↳ 能力清单约束   ↳ 风险裁决与授权门禁     │
└───────────────┬──────────────────────────────────────────────┘
                ▼
┌──────────────────────────────────────────────────────────────┐
│ 会话状态机 + 审计日志（脱敏）lib/store.ts                        │
└───────────────┬──────────────────────────┬───────────────────┘
                ▼ postMessage              ▼ JSON-RPC 2.0
┌──────────────────────────────┐  ┌────────────────────────────┐
│ 被代驾站点（iframe 承载）        │  │ /api/mcp 标准 MCP 能力服务器 │
│  ├ /sim/city-hospital 医院挂号 │  │  initialize / tools/list    │
│  └ /sim/citizen-hall  医保缴费 │  │  tools/call（高危同样门禁）  │
│  每单元声明 data-cap-id + aria │  └────────────────────────────┘
└──────────────────────────────┘
```

### 3.2 一次代驾的完整链路

1. **输入** → `POST /api/agent`，服务端以 SSE 持续推送事件流；
2. **Planner** 抽取槽位（姓名、证件号、症状、时间…），缺什么就用大白话追问（事件 `ask`）；
3. **RAG** 把口语症状映射到科室；
4. **Navigator** 在当前页能力清单内选动作，输出到 Guardian 裁决；
5. **Guardian** 判定风险等级：`low` 直接执行 / `medium` 脱敏后执行 / `high` 发 `need_confirm` 停住等授权；
6. **执行** → 通过 postMessage 驱动 iframe 内站点更新（事件 `tool` / `page`）；
7. **授权** → 用户点确认后 `POST /api/confirm` 续跑；
8. **Reporter** 生成通俗回执与播报（事件 `receipt` / `done`）。

### 3.3 站点协议（能力优先于 DOM）

一个站点不是一堆 DOM，而是一份**可插拔的能力声明**（`lib/sim/types.ts`）：

```ts
interface SiteDef {
  id: string;
  pages: PageDef[];            // 每页的字段 fields 与动作 actions
  requiredFields: string[];    // 集齐才能开始代驾
  submitActionId: string;      // 高危动作，Guardian 据此强制授权
  extractSlots(text, known): SlotPlan;   // 无密钥时的规则抽取
  buildReceipt(values): Record<string, string>;
}
```

同一份 `SiteDef` 会被编译成三种东西：**前端渲染的页面**、**Agent 可用的能力清单**、**MCP 工具列表**。

> **新增一个站点的成本**：只写一份 `SiteDef` 并登记到 `lib/sim/registry.ts`。Agent 层、安全层、MCP 层、前端渲染器**一行都不用改**——这就是"能力优先于 DOM"落到代码上的收益。

### 3.4 事件流协议

服务端到前端只有一条 SSE 通道，事件类型集中在 `lib/agents/events.ts`：

| 事件 | 含义 |
| --- | --- |
| `agent` / `agent_end` | 某个智能体的增量思考文本 |
| `tool` | 一次动作执行（含 name / args / result / risk） |
| `page` | 页面状态更新（pageId / values / title） |
| `need_confirm` | 高危动作请求人工授权 |
| `ask` | 信息缺失，向用户追问 |
| `notice` | 提示性留痕（如能力语义纠正），不中断流程 |
| `receipt` / `done` | 回执与结束（含 steps 步数、engine 引擎类型） |
| `error` | 异常 |

### 3.6 适老页里的语音智能助手（决策与执行分离）

老人点右下角的「小鱼兒」说一句话，链路是：**听清 → 听懂 → 只做清单里的事 → 说一句回话**。

```
说话（Web Speech API，取 3 个候选里最说得通的那个）
   ↓
理解：关键词 + 取值匹配 + 步骤闸门（规则引擎，离线可用；也可换成大模型）
   ↓
执行：XiaoYuEr.call(能力清单) 或 XiaoYuEr.nav(导航白名单) —— 绝不直接改 DOM
   ↓
回话：气泡文字 + 语音播报（念一遍 / 上一步 这类动作让页面自己播报，不抢话）
```

四条硬约束，和主项目完全一致：

1. **取值只能从「当前可选项」里挑**：`XiaoYuEr.options()` 给出每一步的合法取值，说一个页面上没有的（比如"挂心脏病科"）会被拒绝并回一句"没听明白"；
2. **动作只能在合法步骤上执行**：`select_date` 只在第 3 步生效，在别的步骤上说了会回"这一步还办不了这个，我没有乱动页面"；
3. **高危动作仍要本人授权**：说到"确认预约"只把确认窗叫出来，要么本人点绿色按钮，要么本人再说一声"确认"；
4. **零成本兜底**：没有网络、没有麦克风、没有大模型时，自动降级为「常说的话」点选卡片，一样能办完——全程不出现键盘输入。

想接真实大模型时不用改页面结构，只挂一个决策函数即可；它出错或返回越权动作，自动回落到规则引擎：

```js
window.XiaoYuErAI.setPlanner(async (text, { state, options, capabilities }) => {
  // 返回 { actions: [{ id: 'select_symptom', params: { value: 'leg' } }], reply: '按您说的办' }
});
```

## 四、安全与可控性（不是写在文档里，是硬实现）

1. **风险分级**：`low`（浏览、普通填写）/ `medium`（身份证、手机号等隐私字段）/ `high`（提交、支付、删除）；
2. **人工授权门禁**：`high` 级动作必须本人点击授权才可执行，授权记录进审计日志；拒绝则流程终止，**绝不提交**；
3. **敏感值脱敏**：身份证 `110105********1234`、手机 `138****8000`，真实值只存在于会话内存，界面与日志另有输出侧兜底过滤；
4. **提示词注入检测**：覆盖「覆盖系统指令 / 套取系统提示词 / 角色劫持 / **绕过人工授权**」四类意图，命中即在进入模型前拦截并回传具体原因；
5. **防幻觉闸门**：Navigator 输出的动作 id 若不在当前页能力清单内，直接丢弃并重试；MCP 通道的 `tools/call` 同样受此约束，越权调用返回可用能力列表而不执行；
6. **双链路兜底**：模型不可用或输出不可解析时，自动切换到确定性规则引擎，流程照样跑完。

**想在异地（不在同一网络）访问**，局域网地址就不够用了，两条路：

- 把服务部署到有公网 IP 的机器或云主机上——见「七、部署」，本项目无数据库无外部依赖，单端口即可；

### 5.5 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `EADDRINUSE: port 3000` | 端口被占用。Windows：`netstat -ano \| findstr :3000` 找到 PID 后 `taskkill /PID <PID> /F`；或改用 `npx next dev -p 3100` |

| 页面样式异常 | 停掉服务后重新 `npm run dev`，Tailwind 需要重新编译 |
| **电脑上正常、手机上中文全是乱码** | 不是页面坏了，是编码没声明到位 —— 见 5.6 |

### 5.6 手机上打开是乱码怎么办

**现象**：电脑上一切正常，手机（尤其是国产浏览器内核）打开后中文全是问号、方块或「锟斤拷」。

**原因**：文件本身确实是 UTF-8，但常见静态服务器只对 `.html` / `.js` / `.css` 返回
`text/html` / `text/javascript` / `text/css`，**不带 `charset`**。HTML 还能靠 `<meta charset>` 自救；
外链的 JS 和 CSS 没有任何编码线索，手机浏览器只能靠猜，猜成 GBK 就乱码了 —— 本项目 `app.js` 里有三千多个汉字，
一旦猜错，页面文案就全乱。这也是「电脑上好好的、手机上乱码」的典型成因。

**本项目已经做了三层防护**，正常情况下不会再遇到：

| 层次 | 做法 |
| --- | --- |
| HTML | `<meta charset="utf-8">`，外加一条老式 `http-equiv` 兜底（部分国产内核只认它） |
| 外链 | `<link>` 与 `<script>` 都显式写了 `charset="utf-8"` |
| CSS | 文件首行 `@charset "UTF-8";` |
| JS | 文件带 UTF-8 BOM —— 外链脚本唯一的编码线索 |

**还不放心，就用最稳的一招：单文件版。**

```bash
npm run build:elder
```

它会生成 `public/elder/standalone.html`（约 175 KB），把 CSS 与 JS **全部内联进 HTML**，
页面编码从此只由 `<meta charset>` 决定，手机上一定认。这一个文件可以直接传到手机打开，也可以单独上传。

**如果是自己起服务**，请用项目自带的（与 `python -m http.server` 不同，它对所有文本响应强制带 `charset=utf-8`）：

```bash
npm run serve:static            # 服务 out/
npm run serve:static elder      # 服务适老挂号页
npm run serve:static -p 9000
```

**部署到自己的 nginx / Apache**，在配置里补一行即可：

```nginx
# nginx（放在 server 或 http 块里）
charset utf-8;
```

```apache
# Apache .htaccess
AddDefaultCharset UTF-8
```

**若以上都做了还是乱码**，检查一下响应头里是不是被写死了别的编码 —— HTTP 头的优先级高于 `<meta>`：

```bash
curl -I http://你的地址/index.html | grep -i content-type
# 正确应显示：Content-Type: text/html; charset=utf-8
# 若显示 charset=gbk 或 charset=iso-8859-1，那就是服务器配置覆盖了，改服务器配置才有效
```

## 七、部署

本项目有两种形态，**按需二选一**：

| 形态 | 命令 | 产物 | 适用场景 |
| --- | --- | --- | --- |
| 静态站点（推荐先试） | `npm run build:static` | `out/` 纯 HTML/CSS/JS | 丢到任意静态空间即可用 http 打开，**不需要 Node 服务** |
| 服务端应用 | `npm run build` + `npm run start` | Node HTTP 服务 | 需要 `/api/*` 接口、需要接在线大模型 |

### 7.1 静态站点（不需要服务器，放哪都能开）

```bash
npm run build:static     # 产出 out/ 目录（约 1.4 MB，37 个文件）
```

产物是一个完全自包含的静态站点：

```
out/
├─ index.html                 主控台（老人视角）
├─ elder/index.html           适老挂号页（纯静态，零框架）
│  ├─ styles.css / app.js     页面样式与主逻辑（能力清单与代驾接口）
│  ├─ icons.js                29 个内联 SVG 图标（离线可用、零图片请求）
│  ├─ ai.js / ai.css          语音智能助手：语音识别 + 本地意图理解 + 只走能力清单执行
│  └─ standalone.html        单文件版：样式脚本全内联，手机端最稳（由 npm run build:elder 生成）
├─ sim/city-hospital/index.html    被代驾站点·医院挂号
├─ sim/citizen-hall/index.html     被代驾站点·医保缴费
├─ _next/static/...           脚本与样式
└─ 404.html
```

产物里的路径**已全部改成相对路径**（构建时由 `scripts/fix-static-paths.mjs` 处理）。
Next 默认导出的是 `/_next/...` 这类以斜杠开头的绝对路径，只有把 `out/` 放在域名根目录才能打开；
改成相对路径后，双击 `index.html`、或把 `out/` 放到任意二级目录（例如 `example.com/demo/`）都能正常打开。

**怎么打开**（三选一）：

```bash
# 方式一：本地快速预览（任选一种）
cd out && python -m http.server 8080     # 然后打开 http://localhost:8080
cd out && npx serve                       # 或任意静态服务器

# 方式二：上传整个 out/ 目录到任意静态空间
#   对象存储静态托管 / nginx / GitHub Pages / 内网文件服务器……
#   把 out/ 里的内容作为站点根目录，访问 index.html 即可

# 方式三：直接用浏览器打开 out/index.html
```

**静态形态下能力不打折**：代驾流程、四智能体编排、高危动作授权门禁、敏感值脱敏、审计日志、能力语义检索、防幻觉闸门、轨迹回放与导出——全部保留。原因是引擎本来就是纯 TypeScript 实现的，静态形态把它放到浏览器里跑（`lib/runtime/`），与服务端形态共用同一份 `runAgent`，事件序列完全一致。

唯一区别：静态形态没有 `/api/*`，因此 MCP 工具清单改为在浏览器内调用同一份 `lib/mcp/core`，自动化评测改为「浏览器内自检」（打开页面即跑，结果见右侧「自动化评测」面板）。

> 静态形态不需要任何模型密钥：浏览器里取不到 `LLM_API_KEY`，自动走内置规则引擎，与服务端的无密钥兜底是同一条链路，因此**离线也能完整演示**。

### 7.2 本机生产模式

```bash
npm run build     # 生产构建（输出到 .next）
npm run start     # 以生产模式启动，默认 http://localhost:3000
```

### 7.3 自建服务器 / 云主机

```bash
npm install
npm run build
npm run start:cloud    # scripts/start-cloud.mjs
```

`start:cloud` 由 Node 读取环境变量 `PORT` 后传给 `next start -H 0.0.0.0`，**不依赖 shell 展开 `$PORT`**（部分托管环境不展开 `$PORT`，直接写 `-p $PORT` 会启动失败）。默认无 `PORT` 时回落 3000。

要点：

- 构建放在安装/准备阶段，**不要放在启动阶段**——否则可能吃掉健康检查的超时窗口；
- 若部署环境只开放一个端口，本项目天然适配（只有一个 HTTP 服务）；
- 未配置模型密钥时自动走规则引擎，部署后不依赖任何第三方可用性。

### 7.4 环境变量

生产环境建议显式设置：`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`REQUIRE_HUMAN_CONFIRM=1`。

## 九、实现要点

| 关注维度 | 本项目对应实现 |
| --- | --- |
| 智能体编排 | 四个角色分工协作，思考、动作、观察全程可观测可回放；失败自省会回灌提示词，避免重复无效动作 |
| 大模型集成 | OpenAI 兼容协议，智谱 / SiliconFlow / OpenRouter / 本地 Ollama 任选；无密钥自动降级规则引擎 |
| 检索增强 | 零依赖中文二元组 TF-IDF：口语症状 → 科室映射；动作 id 语义检索（余弦 + 编辑距离融合） |
| 多模态 | 语音输入（Web Speech API）+ 语音播报（speechSynthesis），不支持时自动降级为文字 |
| 工具协议 | 标准 MCP 服务器（JSON-RPC 2.0）：initialize / tools/list / tools/call，高危动作同样受授权门禁 |
| 安全可控 | 三级风险裁决、强制人工授权、提示词注入检测、防幻觉能力闸门、敏感值全程脱敏 |
| 前端工程 | TypeScript strict 零错误、Next.js App Router、SSE 流式渲染、站点无关渲染器、错误边界事件 |
| 实用性 | 两个真实业务流程；缺信息会追问、非法输入会校验、失败可恢复；新增站点成本极低 |
| 用户体验 | 适老大字号高对比、语音输入输出、思考过程可视化、动作高亮联动、键盘焦点环 |
| 社会价值 | 数字鸿沟议题；同一套能力协议可复制到政务 / 社保 / 缴费 / 医院等任意网页流程 |
